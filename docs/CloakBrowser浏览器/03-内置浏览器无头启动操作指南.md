# 内置浏览器无头启动（去弹窗）操作指南

> 迁移轮次：R2（内嵌体验）
> 日期：2026-10-13
> 前置文档：`01-CloakBrowser集成操作指南.md`（cloakserve 本体）、
> `02-采集逆向浏览器栈接入CloakBrowser操作指南.md`（browser_server 收口 + 右栏面板迁移）

## 1. 背景与目标

用户诉求：打开右栏「内置浏览器」，输入网址后**弹出一个独立的 Cloak 浏览器窗口**；
希望不弹窗，把浏览器界面内嵌在右侧边栏里。

**结论先行——这是两个问题，其中"内嵌"其实已经存在：**

- **内嵌 = 右栏镜像面板（已有）**：`bobo/ui-browser-cloak` 的面板以 180ms 轮询 CDP
  截图画在 `<canvas>` 上，鼠标键盘回传真实页面——画面、地址栏、标签栏本来就在侧边栏里。
- **弹窗 = Cloak Chrome 是有头进程（本指南要解决的）**：输入网址并不会新开浏览器，
  而是 CDP 在共享 Chrome 实例里开一个新标签页；但这个实例是带窗口启动的，
  于是每次导航它都会跳到前台，看起来像"弹出来"。

本指南：给 cloakserve 的两处 spawn 加 `--headless`，Chrome 无窗口运行，
用户只看得到侧边栏里的镜像画面——即"内嵌"体验闭环。

> 后续：镜像本身的帧率/延迟优化（screencast 帧缓存，180ms 轮询 → 50ms 拉缓存）
> 见 `04-内置浏览器镜像提速操作指南.md`。两方案正交，04 依赖本指南的 headless 环境。

## 2. 原理：为什么现在会弹窗

```
右栏面板  POST /bobo-cloak/cmd (debug_navigate)
  → bridge.ts（宿主 node 进程）
  → scripts/browser_server.py（TCP 一行 JSON）
  → cloakserve 127.0.0.1:9333（CDP 多路复用）
  → Cloak Chrome 实例  ← 有头窗口，就是它弹出来
```

cloakserve 内部其实**有** headless 配置，但它是坏的：

- `cloak/bin/cloakserve:808` 配置默认 `"headless": True`，
  `main()` 把它传给 `ChromePool(headless=...)`（`:871`）；
- 但这个布尔值最终只影响 `cloakbrowser.build_args()` 里的
  `--ignore-gpu-blocklist` 取舍与视口模拟（`cloak/venv/.../cloakbrowser/browser.py:1442`），
  **`build_args` 全程不生成 `--headless` 命令行参数**；
- 也就是说：不显式传参时，Chrome 永远有头启动——`headless: True` 只是摆设。

而 cloakserve 的 CLI 支持透传：

- 裸 `--headless` 不匹配任何 consumed 前缀，落入 `parse_cli_args` 的
  `passthrough` 分支（`cloak/bin/cloakserve:846`），经 `global_args`
  进 `full_args`（`:367`）**原样传给 Chrome**；
- 因此"去弹窗"只需要在启动 cloakserve 时多带一个 `--headless`。

## 3. 改动清单（2026-10-13 已落地）

两处 spawn 是**仅有的** cloakserve 启动入口，参数必须保持一致（文件头注释互相声明）：

```
修改 cloak/plugin/service.js            宿主层 dsh-cloakbrowser 插件（面板「启动浏览器」按钮链路）
    - startChild()：args 增加 '--headless'（+ 中文注释说明）

修改 scripts/browser_server.py          适配层按需兜底拉起链路
    - ensure_cloakserve()：args 增加 '--headless'（+ 中文注释说明）
    - 文件头 docstring、cloakserve 生命周期段注释同步参数清单：
      --port / --data-dir / --proxy-server / --headless
```

无构建负担：`.dsh/profiles/web/node_modules/dsh-cloakbrowser` 是
`link:../../../cloak/plugin`（源码直载），`browser_server.py` 也是直接执行的脚本，
改完即生效。`py_compile` 与 `node --check` 均通过。

## 4. 操作步骤

### 4.1 修改（重放本指南改动）

`cloak/plugin/service.js` `startChild()` 内：

```js
const args = [cloakservePath, `--port=${port}`, `--data-dir=${dataDir}`, '--headless']
```

`scripts/browser_server.py` `ensure_cloakserve()` 内：

```python
args = [sys.executable, str(script),
        f'--port={CLOAKSERVE_PORT}', f'--data-dir={data_dir}', '--headless']
```

### 4.2 生效前提（重要）

- **只对"新拉起"的 cloakserve 生效**：cloakserve 是共享服务，已运行的实例不会被重启
  （`ensure_cloakserve` 见 9333 活着直接复用）。改完想立即生效，先手动收掉旧实例：

  ```powershell
  # 杀 cloakserve + 它拉起的 cloak Chrome（不要动你自己开着的 Chrome）
  Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
    Where-Object { $_.CommandLine -like '*cloakserve*' } |
    ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" |
    Where-Object { $_.CommandLine -like '*cloak*data*' } |
    ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  ```

- 下一次面板点「启动浏览器」（或任一 crawl/debug/panel op）会自动按新参数拉起。

### 4.3 验证（可复现命令）

```powershell
# ① 语法
.venv\Scripts\python.exe -m py_compile scripts\browser_server.py
node --input-type=module --check < cloak\plugin\service.js

# ② 拉起后：cloakserve 命令行必须带 --headless
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*cloakserve*' } |
  Select-Object ProcessId, CommandLine

# ③ 无弹窗：cloak 的 Chrome 必须没有主窗口
#    （MainWindowHandle 非 0 的只应有你自己的浏览器）
Get-Process chrome | Where-Object { $_.MainWindowHandle -ne 0 } |
  Select-Object Id, MainWindowTitle

# ④ CDP 与画面链路
curl http://127.0.0.1:9333/json/version        # 200
# 走 browser_server 发 ping / debug_navigate / screenshot 三个 op，
# screenshot 返回非空 JPEG base64 即画面可用
```

## 6. 面板组件层点验方法（02 §8.5 遗留 1 的闭环，同日完成）

右栏面板协议层/路由层在 02 §8.4 已验，本轮补齐组件层实点：

1. 启动内核：`启动.cmd`（或直接 `node <kernel> --profile web --port 7075`，
   `DSH_HOME=E:\SmartBoBo\.dsh`）。启动日志里有 `dsh web: http://127.0.0.1:7075/?token=...`
   ——**带 token 访问一次**换取签名 cookie，否则全程 401（`dsh-client-connection` 的
   launch-token 机制，token 每次进程随机）。
2. Playwright 打开该 URL → 右栏折叠时先点 `[data-sidebar-right-expand]` →
   guide 入口 `data-sidebar-right-guide-entry=cloak` → 面板出现。
3. 依次验证：
   - **启动**：点「启动浏览器」→「正在启动浏览器…」→「已连接」，20000 段新端口监听；
   - **镜像画面**：canvas 像素非纯色，连续帧有变化，导航前后画面 diff 明显；
   - **导航**：地址栏输入回车 → `panel_pages` 回包、状态行回填；
   - **键鼠标**：canvas 点击（坐标 contain-fit 映射）触发页面跳转/开标签，
     文本区「发送文本」中文落到页面输入框，Enter 生效，无「操作被拒绝」浮条；
   - **handoff**：同源 `fetch('/bobo-cloak/cmd', {op:'handoff_state'})` → 200，
     4s 轮询稳定（浮出交互需 agent 侧 `setPendingHandoff()` 触发，外部不可注入）。
4. 截图与机器可读结果当时落在 `.temp/acceptance/`（gitignore 临时目录，会随清理消失）。

## 7. 回退方式

删掉两处 `'--headless'` 参数即可（恢复有头弹窗）。无其他残留：
改动只在 spawn 参数与注释，未触碰 op 层、协议、面板前端。

## 8. 风险与遗留

1. **反检测语义变化**：`01` §8 提醒无头可被部分站点检测出来；无头下 cloakbrowser 的
   模拟视口（DEFAULT_VIEWPORT 1920×947）反而生效（有头时被真实窗口覆盖）。
   若目标站点在无头下异常，先怀疑这一点。经验：从面板打开百度/example.com 实测正常。
2. **cloakserve 无法接管已在跑的同 profile 实例**（02 点验中实测的严重隐患）：
   旧 cloakserve 对外部已存在的 Chrome `/json/version` 持续 502，失败重试
   （每次失败 `_safe_rmtree(user_data_dir)`）曾把 `cloak/data/__default__`
   的 History/Login Data/Local Storage 全部删空。本轮 headless 改造不涉及该路径，
   但**收旧实例再拉起**（§4.2）时同样受它影响——务必按 §4.2 的顺序先杀干净再拉起。
   修复建议（未实施）：launch 失败时跳过 rmtree（profile 被占用即放弃），
   并为 cloakserve 增加 DevToolsActivePort adopt 复用。
3. **面板「已连接」探层浅**：`op:start` 只证明 browser_server 端口通，
   cloakserve/CDP 尚未就绪时也可能显示「已连接」，随后画面 op 才失败。
   后续可让 `status` 探到 CDP 层。
4. **面板命令超时 < 后端预算**：面板 `COMMAND_TIMEOUT_MS=15s`，
   而 `debug_navigate` 后端预算 120s——cloakserve 慢启动时面板会误报
   「操作未送达，请重试。」。后端恢复后手动重试即可，未改。
