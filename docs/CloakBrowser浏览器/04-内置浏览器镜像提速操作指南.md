## 1. 背景与目标

方案 A（`03`）落地后弹窗已消失，画面全部内嵌在右栏面板里；但镜像本身的
**帧率与延迟**不满意：

- 旧链路每 180ms 轮询一次 `screenshot` op，服务端每次都 `page.screenshot()`
  （真实渲染 + JPEG 编码，几十 ms）——约 **5.5 fps**，滚动/点击后画面明显滞后；
- 静止页面也照样每帧全量渲染截图，纯浪费。

目标：画面"跟手"（滚动/点击后首帧 ≤ ~100ms），帧率随内容变化而动，
静止页近乎零开销——**且保持无头**（方案 A 的 `--headless` 不动）。

## 2. 原理

### 2.1 为什么不是 WebSocket 推流

原计划"WS 推流"在本架构下不可行：

- 面板 ↔ 宿主桥只能走 `register({ handler(req, res) })` 的 HTTP 路由
  （`bobo/tool-acquisition/src/bridge.ts`），插件拿不到 upgrade 事件，无法注册 WS 端点；
- 宿主 → 页面也没有空闲的推送通道（`handoff-watch.ts` 注明唯一事件席位已占用）。

### 2.2 实际方案：CDP screencast 服务端推帧 + 前端 50ms 拉缓存

```
Chromium --headless
   │  CDP Page.startScreencast：画面变化时推帧（静止不推），需及时 ack 否则停流
   ▼
browser_server.py     帧缓存 _sc（jpeg base64 + seq + 启帧时的 CSS 视口）
   │  screenshot op 只读缓存（锁内微秒级），不再实时渲染
   ▼
bridge（透传，零改动） → 面板 50ms 轮询（请求带 since，服务端无新帧回 unchanged 短包）
```

关键语义：

- **变化即推**：screencast 只在视觉变化时发 `Page.screencastFrame`（事件里立即
  `screencastFrameAck` 保持推流），滚动/动画连续出帧，静止页只留一帧缓存；
- **`since` / `unchanged`**：请求带客户端已见帧序号 `since`；服务端没有更新的帧时
  回 `{ok, unchanged:true, seq, url, title, css_*}`（**不带 base64**，中位 131 字节）——
  静止页轮询近乎零带宽，状态行照常刷新；
- **懒重启**：`_screencast_ensure` 在每次取帧时校验绑定页，换页/切标签/导航后
  自动对新页重启 screencast；首帧未到与 screencast 异常时回退实时
  `page.screenshot`（功能不退化）。

### 2.3 为什么不改 50ms 以下

回包往返（fetch → bridge → TCP → 锁内读缓存 → 返回）实测中位 **9ms**，
50ms 轮询周期下 CPU/带宽可忽略；再压间隔收益递减，且轮询本身会开始与
输入转发争抢浏览器事件循环。20 req/s 是当前的合算点。

## 6. 回退方式

1. 前端：`FRAME_INTERVAL_MS` 改回 180、去掉 `since` 与 `unchanged` 分支、
   `lastSeqRef` 可留可删（不发送即无副作用）；
2. 服务端：`panel_screenshot` 恢复为实时 `page.screenshot` 版本（git 历史即旧版），
   `_sc` 段可整体删除；
3. 只退其一也能工作：服务端新语义向后兼容（不带 `since` 时每帧都带 data）；
   前端退回 180ms 轮询在新服务端上照常显示，只是帧率回到 5.5fps。

## 7. 风险与遗留

1. **静止页"画面不动"是设计语义**：screencast 只在视觉变化时推帧。页面内部
   动画/倒计时等仍会触发推帧；若某站的画面变化未被合成器察觉（极少见），
   面板会停留在最后一帧——点一下刷新按钮（`reload` op）即可。
2. **wheel 偶发无效（1/4 轮未复现）**：换页后立即滚动有一次未生效（`scrollY`
   不动），同面板其余轮次全部正常。疑与焦点/首帧未稳有关，未定位，留意复发。
3. **`已连接` 仍只探到 browser_server 端口**（`03` §8.3 的既有问题）：cloakserve
   实际在首个页面 op 才拉起（本次实测冷启动 10.9s），期间面板显示已连接但
   无画面；拉起后自动恢复，无需人工干预。
4. **cloakserve 手动实例的生命周期**：点验期间发现——手工起的 cloakserve
   （未挂日志重定向）退出无痕迹；由 `ensure_cloakserve` 拉起的实例日志进
   `cloak/cloakserve.log`。排查问题时先确认实例是谁拉的。
5. **headless 保持不变**：本方案与 `03` 的 `--headless` 正交；反检测注意事项
   见 `03` §8.1。
