# 内置浏览器窗口自适应操作指南（默认大视口 + 视口跟随）

> 迁移轮次：R2.2（内嵌体验·窗口形态）
> 日期：2026-10-13
> 前置文档：`03-内置浏览器无头启动操作指南.md`（方案 A 去弹窗）、
> `04-内置浏览器镜像提速操作指南.md`（方案 B screencast 帧缓存）

## 1. 背景与目标

方案 A/B 之后弹窗消失、帧率跟手，但用户感知"画面不能像参考项目一样随窗口形态
变化"。对比调研（`E:\BoBo-Handyman` 的 `ui-browser-camoufox`）结论：

- **参考项目并没有 resize 自适应机制**——两边都是纯 CSS letterbox
  （`object-fit: contain`）、都无 resize 监听、页面视口都固定；
- 真正的差距是 **headless 默认视口太小（764×451）**：画面被拉伸到侧边栏时发糊、
  黑边大，观感僵硬；参考项目 camoufox 有头窗口是 1920×947 级别所以饱满清晰；
- 响应速度上方案 B 后本项目已超过参考项目（50ms+screencast vs 180ms+实时截图）。

本指南两步：**① 默认大视口**（`--window-size` 透传，两行参数）；
**② 视口跟随**（`panel_resize` op，页面视口 = 面板尺寸，拖动即 reflow，1:1 无黑边）。

## 2. 原理

### 2.1 默认大视口（第一步）

cloakserve CLI 的裸参数 passthrough（与 `--headless` 同路径，`cloak/bin/cloakserve:846`）
把 `--window-size=1920,947` 透传给 Chrome。参数顺序上 `global_args` 在 `build_args`
产物之后（`:367`），覆盖 cloakbrowser 自带窗口参数。实测 headless 视口
764×451 → **1904×818**（差值为滚动条等浏览器 UI 占位）。

### 2.2 视口跟随（第二步）

```
面板 surface 尺寸变化（打开/拖动右栏/窗口缩放）
  → ResizeObserver（前端，观察 surfaceRef）
  → 防抖 300ms（拖动连续事件只发终值；<100px 假尺寸忽略；同尺寸跳过）
  → POST /bobo-cloak/cmd {"op":"panel_resize","width":W,"height":H}   ← 新 op
  → bridge 白名单透传
  → browser_server.panel_resize：钳制 [320..2560]×[240..1600]
      → page.set_viewport_size()          页面 reflow
      → _screencast_stop()                缓存帧作废，下一 tick 实时截图兜底出新尺寸首帧
      → _PANEL_WANT 记住期望视口
  → 换页重放：debug_navigate / panel_select / _adopt_popup 成页后
      自动 _apply_panel_viewport()——agent 导航也不掉回默认视口
  → 帧回包 css_width/height = 面板尺寸 → 画面 1:1 无 letterbox
```

效果实测（面板 surface 719×794）：

| 状态 | 视口 → surface | 缩放 | 上下黑边 |
|---|---|---|---|
| 方案 B（旧） | 764×451 → 719×758 | 0.94 | **44%** |
| 本方案未跟随时 | 1904×818 → 719×794 | 0.38 | 61%（所以必须跟随） |
| **本方案跟随后** | 719×794 → 719×794 | **1.00** | **0%** |

## 6. 回退方式

- 只退视口跟随：前端删 ResizeObserver effect（src+lib）、后端 `panel_resize` 回
  `followed:false`（或环境变量 `CLOAK_VIEWPORT_FOLLOW=0` 一行即关）；第一步的
  大视口独立保留，仍饱满（letterbox 缩放显示）；
- 只退大视口：删两处 `--window-size` 参数，视口跟随仍可用（跟随会立刻把视口
  改成面板尺寸，默认值只是跟随前的底）。

## 7. 风险与遗留

1. **共享页语义**：视口跟随使 agent 的采集/调试渲染尺寸随面板变化（爬虫产物
   布局会不同）。需要锁定时用 `CLOAK_VIEWPORT_FOLLOW=0` 重启会话。
2. **窄面板 + 横向溢出页面**：视口跟到 ~480px 时，宽布局页面（如百度搜索框）
   元素中心可能落在视口外——按"元素中心"操作面板会映射出界。属被跟随页面的
   布局溢出 + `pointAt` 钳制的组合表现，非转发缺陷；面板拖宽即恢复。
3. **【既有·点验中再次复现】每次「启动浏览器」spawn 出 2 个 browser_server**：
   创建时间差 ~28ms，仅一个监听派生端口，另一个空转。疑似
   `CloakBrowserService.start()` 并发竞态（peer 探测窗口）。方案 B 点验同样观察到，
   非本轮引入；建议后续在 browser-server.ts 的 start 加进程内单飞锁。
4. **拖动期间的 reflow 成本**：防抖后单次 `set_viewport_size` 对大页有几十 ms
   重排，期间 `_page_lock` 会短暂阻塞输入一瞬——实测无感知。
5. **参考项目对照结论**：参考项目（camoufox）无 resize 机制且帧率更慢
   （180ms+实时截图）；本方案落地后本项目在"窗口自适应 + 响应速度"两维均超过参考项目。
