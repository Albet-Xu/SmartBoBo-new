> 迁移轮次：R3.1（真浏览器体验·中文输入）
> 日期：2026-10-13
> 前置文档：`02-采集逆向浏览器栈接入CloakBrowser操作指南.md`（面板与桥）、
> `06-内置浏览器起始页与AI读页操作指南.md`（iTab 起始页 + browser_read_current）

## 1. 背景与目标

用户反馈：在面板画面里（如 iTab 搜索框）**无法用中文输入法打字，只能输入英文字母**。

排查结论（非 bug，是设计边界）：画面是 div+canvas 镜像，不是可编辑 DOM——
系统 IME 无处建立组字会话；旧 `onKeyDown` 还会把拼音字母逐个 `insert` 成英文。
设计上的中文路径一直是面板下方的「文本发送区」（`insert_text`），两步操作有落差。

目标：**画面上直接打中文**——本地 IME 正常组字（系统候选窗可见），缓冲实时
镜像进远程输入框（能看到拼音逐字出现），确认上屏汉字。即路线②"远程 IME 镜像"。

## 2. 原理

### 2.1 CDP IME API（Spike 已实证）

Chromium 为远程桌面/云桌面提供的官方 IME 通道：

```
Input.imeSetComposition(text, selectionStart, selectionEnd, x?, y?)
    → 远程输入框实时显示组字缓冲（"nihao"）
Input.insertText(text)
    → 用最终文本替换整个组合区并结束组合（"你好"上屏）
```

实测（headless + cloakserve WS 代理下**完全可用**）：input 元素与 contenteditable
富文本均通过；连续两轮组合正确追加。

### 2.2 全链路

```
系统 IME 组字（载体：跟随鼠标的透明 textarea，1×1px opacity 0）
  │ compositionstart / compositionupdate(缓冲) / compositionend(最终文本)
  ▼
前端：去重 + 串行 Promise 队列（commit 必须晚于最后一个 compose 抵达）
  ├─ {"op":"ime","action":"compose","text":"nihao","x":..,"y":..}
  └─ {"op":"ime","action":"commit","text":"你好"}
  ▼
bridge FORWARDED_OPS 透传（+'ime'）
  ▼
browser_server.panel_ime（_page_lock 内）
  ├─ compose → Input.imeSetComposition
  └─ commit  → Input.insertText
  （独立缓存 cdp session，换页惰性重建）
  ▼
远程输入框：拼音逐字可见 → 汉字上屏（screencast 画面同步）
```

### 2.3 三个关键设计点

1. **载体跟随鼠标**（`parkIme`）：点击画面时把透明 textarea 摆到点击处再 focus——
   系统候选窗锚定 textarea 光标，于是**候选窗出现在你点击的输入框旁边**；
2. **焦点时序陷阱**：浏览器 mousedown 的默认焦点动作（聚焦最近可聚焦祖先 =
   surface div）发生在 pointerdown handler **之后**，会把焦点抢走——
   修复：`onPointerUp` 里补一次 `focus()`（此时默认动作已全部结束，必定生效）。
   点验实测修复前可信点击后焦点落在 surface ❌、修复后 3/3 落在载体 ✅；
3. **isComposing 旁路**：`onKeyDown` 开头 `if (event.isComposing || event.keyCode === 229) return`
   ——组字期的 keydown 不再被拆成英文字母直输（这是"只能打字母"的直接病灶）；
   非组字按键（英文/Enter/方向键）完全走旧路径，零行为变化。

## 6. 回退方式

- 前端：删透明 textarea 与 composition 处理（src+lib）、去掉 isComposing 旁路与
  park/focus 两处——回到"中文只能走下方文本发送区"；
- 服务端：`panel_ime` 与分发分支可留存（无调用方即闲置），或一并删除；
- 桥：`FORWARDED_OPS` 删 `'ime'`。

## 7. 已知限制与遗留

1. **拼音缓冲在远程输入框内可见，但候选列表是系统级 UI**（跟随本地载体光标 =
   点击处）；远程页面自身的输入法相关 UI（如部分站点的自绘候选）不适用。
2. **组字中途点击别处**：compositionend 会以当时缓冲上屏到新位置（与本地
   浏览器行为一致）；blur 丢弃半截拼音的精细化处理本期未做。
3. **真机 IME 手测待用户完成**：自动化已覆盖合成事件链与服务端全链路，
   但微软拼音/搜狗的真实组字手感（候选窗定位、上屏节奏）需你在面板里
   实际打一段中文确认——iTab 搜索框、百度搜索框、B 站评论框三类场景。
4. 既有遗留不回归：双 browser_server 进程（05 §7.3）、cloakserve rmtree
   （02 §8.5.4）、goHome 并发误报浮条（06 §7.1）。
