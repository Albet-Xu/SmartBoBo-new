# 代理池功能实现操作指南

> 从参考项目 BoBo-Handyman 迁移。迁移日期：2026-10-12。
> 功能：配置多个商业代理 API 源，`/proxy` 命令开启会话级代理模式后，`cloak_fetch` 采集自动走代理池出口 IP，规避反爬。

---

## 1. 功能概述

- **代理池** = HTTP 代理 IP 池（不是 AI 代理）。从多个代理 API 批量拉取 IP，探测存活后喂给 CloakBrowser。
- **`/proxy` 命令**：会话内开关代理模式（`/proxy on` / `/proxy off` / 无参 = on）。状态写入会话日志事件 `proxy/enabled`，由 `proxyMode` 投影折叠（最后一条取胜）。
- **设置页**：设置 →「代理池」管理 API 源（名称/URL/密钥/取数参数/启停），支持拖拽排序；取用策略 `cache`（批量轮询复用）或 `realtime`（每次拉新）。
- **失败台账**：探测失败的 IP 记入 `data/proxy_failed.json`，15 分钟 TTL 内不再复用。
- **筛选机制**：`proxy_pool.py` 最多 3 轮、每轮最多探测 10 个、单个超时 8s；任一 HTTP 响应即算通（403 不判死）。3 轮全失效才报失败。

### 与参考项目的差异（cloak 对接）

参考项目的采集引擎是 Camoufox（`tool-acquisition/crawl-tool.ts` → `browser_server.py --proxy`）。SmartBoBo 用 CloakBrowser（`cloak/plugin`），且 **cloakserve 的代理是服务级的**（启动时注入，运行中改代理需重启服务）。因此代理集成做在 cloak 插件内部：

1. `cloak_fetch` 执行前检查当前会话 `proxy/enabled` 事件；
2. 开启则调 `proxy_pool.py --action get` 取代理；
3. 代理与当前 cloakserve 启动参数不一致时，`dispose` 旧服务、带 `--proxy-server=<代理>` 重启；
4. 池内 3 轮全失效 → 返回「代理失效，是否走本地网络进行访问网页？」让模型询问用户。

### command-proxy 的依赖处理（重要）

参考项目在 dsh monorepo 内用 workspace 解析依赖；SmartBoBo 的插件在 `bobo/` 下，裸导入靠 `bobo/node_modules`（Node 从 `bobo/command-proxy/lib/index.js` 向上查找）。内核版本 0.2.0-rc.2，需从 `%APPDATA%\dsh-tauri\dependencies\dsh\node_modules\` 复制**同版本**的：

```
zod                          (4.6.5)
@deepseek-ai/schemastery     (3.18.4 → 依赖 cosmokit ~1.8.5、@standard-schema/spec ^1.1.0)
@deepseek-ai/cosmokit
@standard-schema/spec
```

另：`lib/index.js` 顶部原本 `import { createUserMessage } from "@deepseek-ai/dsh-llm"`，dsh-llm 传递依赖太重（cordis/typert 等），已改为内联等价实现（`{...input, role:'user', id: randomUUID()}`），行为一致。

`bobo/node_modules` 不进版本库（`.gitignore` 的 `node_modules/` 规则）。新环境或内核升级后执行：

```powershell
powershell -ExecutionPolicy Bypass -File E:\SmartBoBo\bobo\ensure-deps.ps1
```

> **补记（市场预设迁移后）**：`ensure-deps.ps1` 现在除了上面 4 个**复制**，还会创建 4 个**目录联接**：
> `@deepseek-ai/dsh-llm`、`dsh-tools`、`dsh-home-paths`、`dsh-skill`，目标都是内核自己的
> `%APPDATA%\dsh-tauri\dependencies\dsh\node_modules\@deepseek-ai\<pkg>`。
> 用联接而不是复制，是为了让这些包与宿主共享**同一份模块实例**（它们要消费内核的 live
> cordis 服务）；Node 默认把符号链接还原成真实路径，所以解析结果就是内核那一个文件。
> 联接不进版本库（`node_modules/` 被 gitignore），新环境同样靠这条命令重建。
> 详见《04-市场预设可用化操作指南.md》。

## 3. 接线明细

### 3.1 profile 插件挂载（`.dsh/profiles/web/cordis.patch.yml`）

```yaml
- id: proxy-pool
  name: '../../../bobo/command-proxy/lib/index.js'
- id: ui-settings-proxy
  name: '../../../bobo/ui-settings-proxy/lib/index.js'
```

相对 name 以 cordis.patch.yml 所在目录（`.dsh/profiles/web/`）为基准锚定。`proxy-pool` 条目的 volatile Config 即设置页数据源（`namespace/projection/command` 三个开关默认全开；SmartBoBo 不按预设拆分实例，宿主单例即可）。

### 3.2 cloak 插件（运行时链路）

```
用户 /proxy on
  → command-proxy：session.append('proxy/enabled', {enabled:true}) + projection 落库
cloak_fetch 执行（cloak/plugin/tools/cloak-fetch.js）
  → SessionProxyMode.of(exec.agent.session)   ← cloak/plugin/proxy.js，订阅 ctx.on('session/event')
  → 开启则 proxyPoolOf(ctx.get('settings'))   ← 读 ns='proxy-pool' 的 describe 投影
  → acquireProxy(pythonBin, scriptsDir, pool, url, timeout, signal)
      子进程：.venv/Scripts/python.exe scripts/proxy_pool.py --action get
              --config-json '{sources,fetchStrategy,timeoutMs}' --target-url <url>
  → runtime.ensureProxy(proxy)                ← cloak/plugin/service.js
      代理与 currentProxy 不同 → dispose 旧 cloakserve → startChild 带 --proxy-server=<proxy>
  → runtime.ensureReady() → CDP 连接 → page.goto
失败（池 3 轮全灭）
  → 返回 {ok:false, error:'代理失效，是否走本地网络进行访问网页？'} → 模型 ask_user
```

`settings` 用惰性 `() => ctx.get('settings')`：apply 时服务可能未就绪，fetch 时再取。

### 3.3 Python 依赖（`pyproject.toml`）

```toml
"httpx>=0.27",        # proxy_pool.py 的 API 拉取与探测
```

执行 `uv sync` 安装。

### 3.4 设置页导航图标（两处补丁）

设置导航栏的字形**不由注册方决定**：章节注册（`settings.section`）只携带 `id/order/label`，图标是按 section id 在一张硬编码映射表里查的，查不到就落兜底齿轮。所以只能改渲染设置面板的那份代码。

本项目实际有两套设置面板实现，两处都补了（互为兜底）：

| 渲染方 | 何时生效 | 补丁位置 |
|---|---|---|
| `dsh-tauri-ui`（第三方插件，**当前实际生效**） | profile 装了该插件时（本项目即如此，占用 `shell.overlay`） | 给它的 `fn={…}` 映射表加 `"proxy-pool"` / `"experience-pool"` 两个条目 |
| 内核 `ui-settings-general`（上游外壳） | 未装/禁用 `dsh-tauri-ui` 时 | 给 `navIcon(id)` 的兜底 `return` 前插两个分支 |

两处都复用参考项目 BoBo-Handyman 的字形：**代理池 → `IconApiOutline`，经验池 → `IconSparkle`**（沿用内核 `ui-primitives` 的原始 path 数据，视觉与参考项目一致，不新增图标文件）。

补丁由 `scripts/apply-brand-patch.mjs` 在 `启动.cmd` 每次启动时执行（幂等）：

```
targets:
  %APPDATA%\dsh-tauri\dependencies\dsh\node_modules\@deepseek-ai\dsh-client-ui-settings-general\lib\client.js   ← 内核外壳
  <profile 里 dsh-tauri-ui 的 link 目标>\dist\client.cjs                                                        ← 实际渲染方
```

`dsh-tauri-ui` 的路径从 profile 的 `package.json`（`"dsh-tauri-ui": "link:…"`）解析，不写死；插件升到新目录也能命中。

> **踩坑记录**：`dsh-tauri-ui` 的 `dist/client.cjs` 整个模块体包在一个**模板字符串**里（内部反引号全部写成 `` \` ``）。往里插代码时若用反引号或写 `${`，会截断外层模板串，插件直接挂掉（症状：设置面板打不开、侧栏残缺）。因此插入代码一律用双引号字符串。改完务必 `node --check <该文件>`。
>
> 内核或该插件被桌面端重新下载/覆盖后，图标会回到兜底齿轮，重跑 `node scripts/apply-brand-patch.mjs` 即可（正常从 `启动.cmd` 启动会自动补）。

## 4. 使用方法

1. **配置代理源**：设置 → 代理池 → 添加源（商业代理 API 的 `apiUrl`/`apiKey`/取数参数），启用并保存。
2. **开会话**：在需要采集的会话里输入 `/proxy on`（或 `/proxy`）。
3. **采集**：模型调用 `cloak_fetch` 时自动经代理池出口访问；`/proxy off` 切回本地网络。
4. **失效处理**：池内候选全灭时 `cloak_fetch` 返回询问文案，模型用 ask_user 问用户是否走本地网络。

> 注意：代理只在 cloakserve **启动时**注入。会话中途切换代理会重启 cloakserve（当前页面状态丢失，重新导航）。这是 cloakserve 的服务级限制，与参考项目 Camoufox 结论一致。

## 5. 排障

| 症状 | 原因与处理 |
|---|---|
| `/proxy on` 提示「代理池没有可用代理」 | 设置页里池开关关闭、无启用源、或源 apiUrl 为空（`poolServesAddress` 防呆）。去设置页检查。 |
| `cloak_fetch` 报「代理池返回非 JSON」 | `proxy_pool.py` 崩溃或 python 路径不对。手测：`.venv/Scripts/python.exe scripts/proxy_pool.py --action get --config-json '{"sources":[...]}' --target-url https://example.com` |
| `cloak_fetch` 报「代理失效，是否走本地网络」 | 3 轮筛选全灭（代理商额度耗尽/目标站封代理段）。换源或走本地。 |
| 代理开了但流量没走代理 | cloakserve 未带 `--proxy-server` 重启成功。查 `cloak/cloakserve.log`；确认 `runtime.ensureProxy` 后 `ensureReady` 重新拉起了服务。 |
| 设置页没有「代理池」卡片 | `cordis.patch.yml` 的 `ui-settings-proxy` 行没生效或浏览器端未刷新。后端日志 grep `ui-settings-proxy`。 |
| 插件导入报 `Cannot find package '@deepseek-ai/...'` | `bobo/node_modules/` 缺包。从打包内核 `node_modules` 补齐（见 §2）。 |
