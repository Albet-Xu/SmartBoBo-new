# 经验池功能实现操作指南

> 从参考项目 BoBo-Handyman 迁移。迁移日期：2026-10-12。
> 功能：Agent 的 RAG 记忆库——历史任务（网页逆向/论文写作/文献汇报）的成功/失败经验沉淀为「本地 MD + Qdrant 向量索引」，同类任务先检索历史案例，避免重复踩坑。
> 服务端：**完全复用**阿里云参考项目已有的 Qdrant 与授权网关，服务器未新建任何内容。

---

## 1. 功能概述

三个经验池实例（共享同一份连接配置 `experience-pool.json`）：

| 池 | 本地数据目录 | Qdrant 集合 | MCP serverName | 工具前缀 |
|---|---|---|---|---|
| 逆向 `reverse` | `reverse-experience/` | `reverse_experience` | `reverse-memory` | `mcp__reverse-memory__reverse_memory_*` |
| 论文 `paper` | `paper-experience/` | `paper_experience` | `paper-memory` | `mcp__paper-memory__paper_experience_*` |
| 汇报 `report` | `report-experience/` | `report_experience` | `report-memory` | `mcp__report-memory__report_experience_*` |

### 核心规则

- **本地 MD + registry.json 是事实源，Qdrant 只是索引**（同步失败置 `qdrant_pending` 本地兜底）。
- **入库门槛**：置信度**严格大于 2.0** 才入库；`feedback` 成功 +0.5 / 失败 -0.5，跌破 2.0 删向量点 + 本地归档。
- **检索降级**：Qdrant 不可达 → 本地 registry 评分检索（`mode: local`），不阻塞干活。
- **强制闸门**（dsh 插件）：`readiness.json ready:true` 时，绑定的预设会话「动手前必 search、收尾前必 save」，否则 deny；同一目标连拒 3 次放行防卡死（fail-open 硬约束：闸门只在经验库就绪时生效）。

### 与参考项目的差异

- 参考项目有 3 份需同步维护的 store 实现（`experience-store/experience_store.py` 共享机制层 + `reverse-experience/memory_store.py` 独立实现）；本项目**原样迁移两份**（reverse 仍是独立实现，paper/report 走共享机制层），暂不合并。
- **付费授权网关（bobo-api 的 license 部分）**：客户端设置页（授权卡/迁移/诊断）已迁移；服务端复用阿里云已有部署。本机到 `www.smartbobo.cn:443` 的 TLS 受网络环境干扰（见 §5），**数据面直连 Qdrant 6333**（与参考项目生产实际一致——其 readiness 记录 `qdrant_source: dbx` 直连）。

## 4. 接线明细

### 4.1 连接配置（`experience-pool.json`，项目根）

```json
{
  "enabled": true,
  "url": "http://47.102.138.180:6333",
  "token": "<QDRANT_API_KEY>",
  "readonly": false
}
```

解析优先级（`resolve_endpoint`）：`experience-pool.json` > env `*_MEMORY_QDRANT_URL` > DBX qdrant 连接。三池共享此文件。

> 为什么直连而不是走网关 `/v1/qdrant`：参考项目生产 readiness 记录即为直连 6333（source=dbx）；且本机到网关 443 的 TLS 握手被网络环境重置（openssl TLS1.3 单发可过、Python/curl 全挂），直连 6333 稳定可用。网关仍服务于设置页的授权/迁移/诊断（浏览器端发起，用户网络各异）。

### 4.2 profile 挂载（`.dsh/profiles/web/cordis.patch.yml`）

```yaml
# 设置页
- id: experience-pool
  name: '../../../bobo/ui-settings-experience/lib/index.js'

# 三个 MCP server（宿主层，全部会话可用）
- id: mcp-reverse-memory
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: reverse-memory
    transport: stdio
    command: 'E:\SmartBoBo\.venv\Scripts\python.exe'
    args: ['E:\SmartBoBo\scripts\reverse_memory_server.py']
    env:
      DSH_HOME: 'E:\SmartBoBo\.dsh'    # MCP 子进程环境被清洗，必须显式回传
      BOBO_ROOT: 'E:\SmartBoBo'         # 技能查找用
    toolCallTimeoutMs: 60000
    reconnect: { enabled: true, initialDelayMs: 500, maxDelayMs: 30000, maxAttempts: 10 }
# paper/report 同构（serverName: paper-memory / report-memory）

# 会话粘性状态 + 三个闸门 + 沉淀反思
- id: session-state
  name: '../../../bobo/plugins/session-state.mjs'
- id: reverse-memory-gate
  name: '../../../bobo/plugins/reverse-memory-gate.mjs'
  config:
    preset: reverse          # 与 agentPresets.composedPreset 比对；不匹配即 fail-closed 静默
    searchTool: mcp__reverse-memory__reverse_memory_search
    saveTool: mcp__reverse-memory__reverse_memory_save
    gatedTools: ['mcp__camoufox-debug__debug_navigate']   # 随逆向预设迁移启用
    closeTools: ['mcp__camoufox-debug__debug_close']
    lazyReminders: true
    lazyToolPrefix: 'mcp__reverse-memory__'
    activationTriggers: ['逆向','反爬','爬取','抓取','破解','爬虫','采集','抓包','写爬虫','签名','验证码','风控','混淆','加密','cookie','数据接口']
# paper/report 闸门、experience-reflect 同理（preset: paper / report / reverse）
```

> **闸门当前状态**：本项目尚未迁移研究模式预设（reverse/paper/report），闸门按 `config.preset` 与会话实际预设比对，恒不匹配 → **静默停用**（fail-closed 设计，零副作用）。迁移预设后自动生效。迁移预设前的已知代价：经验池工具 schema 常驻每个请求（闸门的懒露出未激活）。

## 5. 使用方法

1. **检查就绪**：任意会话让模型调 `mcp__reverse-memory__reverse_memory_stats`，或 CLI 手测（见 §6）。`ready: true` 即全链路通。
2. **检索**：`reverse_memory_search(domain='example.com', tags=['js混淆'], features='观察到的特征')`——命中只当待验证假设，禁止照搬。
3. **沉淀**：任务结束调 `reverse_memory_save(...)`，置信度如实自评（>2.0 才入库）。
4. **反馈**：采纳过的经验按结果调 `reverse_memory_feedback(id, 'success'|'fail')`。
5. **设置页**：设置 →「经验池」查看连接诊断、授权状态（网关）、迁移入口。
6. **手动运维 CLI**：

```powershell
$env:DSH_HOME='E:\SmartBoBo\.dsh'; $env:BOBO_ROOT='E:\SmartBoBo'
E:\SmartBoBo\.venv\Scripts\python.exe E:\SmartBoBo\skills\reverse-experience\memory_store.py stats
E:\SmartBoBo\.venv\Scripts\python.exe E:\SmartBoBo\skills\reverse-experience\memory_store.py search --domain csdn.net
E:\SmartBoBo\.venv\Scripts\python.exe E:\SmartBoBo\skills\reverse-experience\memory_store.py sync
E:\SmartBoBo\.venv\Scripts\python.exe E:\SmartBoBo\skills\reverse-experience\memory_store.py purge --apply   # 清存量 ≤2.0，慎用
```

## 6. 排障

| 症状 | 原因与处理 |
|---|---|
| `readiness` 里 `qdrant_reachable: false` + SSL EOF 错误 | 你把 `experience-pool.json` 的 url 改成了网关 HTTPS。本机到 `www.smartbobo.cn:443` TLS 受干扰，改回直连 `http://47.102.138.180:6333` + QDRANT_API_KEY（或换网络环境再试网关）。 |
| MCP server 起不来 / 找不到 memory_store | 检查挂载 env：`BOBO_ROOT=E:\SmartBoBo`（技能在 `skills/` 下）、`DSH_HOME=E:\SmartBoBo\.dsh`。 |
| 检索全部 `mode: local` | Qdrant 不可达但本地兜底正常。查 `experience-pool.json` 与网络。 |
| save 后 Qdrant 查不到 | 置信度 ≤2.0 被门槛丢弃（设计行为）；或同步失败置 `qdrant_pending`，跑 `memory_store.py sync` 补推。 |
| 闸门没有拦截 | 预期行为：预设未迁移时闸门 fail-closed 静默。迁移 reverse 预设且 `ready:true` 后才生效。 |
| fastembed 下载模型失败 | 设 `HF_ENDPOINT=https://hf-mirror.com` 后重试；或确认 `%TEMP%\fastembed_cache` 缓存存在。 |
| 设置页授权卡报错 | 授权卡从浏览器直连 `https://www.smartbobo.cn`，与本机 CLI 的 TLS 环境无关；检查网络或服务器网关状态（服务器侧 `/v1/health` 正常）。 |
| `Api key is used with an insecure connection` 警告 | 直连 6333 是 HTTP（与参考项目一致），警告无害。 |
