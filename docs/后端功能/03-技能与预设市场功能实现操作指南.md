## 1. 这是什么

参考项目的「技能与预设市场」是四层结构的叠加：

```
静态市场站 (nginx)  →  纯 Node 装包核心 (.mjs)  →  宿主服务/RPC  →  设置页 UI
```

本次迁移的做法是 **搬逻辑、不搬架构**：

| 层 | 参考项目 | 本项目 |
| --- | --- | --- |
| 市场站 | 自建 nginx `http://47.102.138.180`，`x-repo-token` 鉴权 | **同一个站**，同一个 token |
| 装包核心 | `plugins/repo-core.mjs` + `market-core.mjs`（纯 Node ESM） | **逐字复制**，见 §6 的三处偏差 |
| 宿主面 | Typert 远端命名空间 `pluginRepo`（`repo.mjs`） | 换成 `dsh-tauri-extension` 既有的 `dsh-h3` HTTP 路由（`/api/tauri/extension/repo/*`、`/market/*`） |
| 预设挂载 | `bobo/presets/include.mjs`（`bobo-preset-includes`） | `bobo/plugins/preset-includes.mjs`（同一套 `cordis:include` 机制） |
| UI | 独立设置页 `bobo-repo-ui`（4 个 Pill tab，CSS Modules + `dsh-client-ui-primitives`） | 面板内的两个 tab + 技能 tab 内的市场弹窗（Tailwind + `dsh-tauri-ui`） |

**为什么要换宿主面**：参考项目用 Typert `@Remote` 装饰器把方法暴露成 RPC，客户端靠
`ctx.remote.pluginRepo.*` 调；它把协议包的依赖用相对路径指进 `dsh/packages/**` 的源码树，
而本项目的 bobo 包在 dsh 工作区**外面**（`bobo/`），那些相对路径全断。此外
`TypertRemoteService extends Service`，从插件自身位置再解析一份协议包会与运行中的内核
分裂类身份。本项目走 HTTP 路由既绕开这两件事，也和已有的「技能」「MCP」两个 tab 写法一致。

## 3. 让它生效（必须手动执行）

工作区的 `dsh/packages/dsh-tauri-extension` **不是运行中的那一份**：`.dsh/profiles/web/package.json`
把 `dsh-tauri-extension` 链到了 `vendor/dsh-resources/node_modules/dsh-tauri-extension`（迁移前
构建出来的产物）。所以改完源码要构建 + 重指 link。

> 这里的三条命令**故意不自动执行**：`dsh/AGENTS.md` 规定「处理或重构插件相关代码时切勿执行
> 构建命令」（用户可能正处于 dev 热重载状态）。

**第 1 步：构建插件**（在 `E:\SmartBoBo\dsh` 下）

```bash
pnpm --filter dsh-tauri-extension build
```

成功后应有 `dsh/packages/dsh-tauri-extension/dist/{index.js,client.cjs}`。

**第 2 步：把 profile 的 link 指到本地构建产物**

编辑 `E:\SmartBoBo\.dsh\profiles\web\package.json`：

```diff
-    "dsh-tauri-extension": "link:../../../vendor/dsh-resources/node_modules/dsh-tauri-extension",
+    "dsh-tauri-extension": "link:E:/SmartBoBo/dsh/packages/dsh-tauri-extension",
```

（和已有的 `dsh-tauri-brand` 同款写法。）

**第 3 步：重启**

```bash
启动.cmd
```

## 5. 数据落点与目录约定

`DSH_HOME` = `E:\SmartBoBo\.dsh`（由 `启动.cmd` 设置）。所有落点与参考项目一致：

| 内容 | 路径 | 谁写 |
| --- | --- | --- |
| 预设 | `<DSH_HOME>/.agent-presets/<id>/` | `repo-core.mjs::installPreset` |
| 工具 | `<DSH_HOME>/.bobo-market/tools/<dir>/` | `installTool` |
| 技能（仓库装的） | `<DSH_HOME>/skills/<id>/` | `installSkill` |
| 技能（第三方市场装的） | `<DSH_HOME>/skills/<dirName>/` + `.market-meta.json` | `market-core.mjs` |
| 安装台账 | `<DSH_HOME>/.bobo-market/state.json` | 两者共用 |
| 下载缓存 | `<DSH_HOME>/.bobo-market/downloads/*.zip` | `repo.ts::install` |
| 详情缓存 | `<DSH_HOME>/.bobo-market/details/<id>.{md,json}` | `repo.ts::get` |
| 预设声明挂载合成文件 | `<DSH_HOME>/cache/preset-includes.yml` | `preset-includes.mjs` |

**技能为什么自动出现在「技能」tab**：`<DSH_HOME>/skills` 正是内核 skill filesystem 的
`user-dsh` root（`@deepseek-ai/dsh-skill-filesystem` 的 `roots()`），而扩展的「技能」tab 走内核
`skills.list()`。所以市场装出来的技能落盘即被发现，现有的删除按钮也直接可用 —— 这正是
「第三方技能并进技能 tab」几乎零成本的原因。

**预设为什么必须重启**：DSH 0.2.0 的 `agent-preset-registry` **不扫任何目录**，只认声明行
（`@deepseek-ai/dsh-agent-preset` 的 `config.plugins`）。`preset-includes.mjs` 只在宿主启动时
扫一次 `<DSH_HOME>/.agent-presets/*/decl.yml` 并挂成 `cordis:include`，所以装完要重启。

## 6. 已知限制（请先读这一段）

### 6.1 市场的 8 个预设在本项目**装得上、但不会生效**

实测（§4.4 第 6 行）：`reverse` 的 16 条 `../../` 装配行全部正确改写成了
`file:///E:/SmartBoBo/bobo/...`，但其中 **5 个目标文件在本项目不存在**：

```
bobo/plugins/bobo-common.mjs
bobo/plugins/collab-gate.mjs
bobo/tool-acquisition/lib/handoff.js
bobo/command-skill-model/lib/index.js
bobo/tool-market/lib/index.js
```

`bobo/plugins/reverse-memory-gate.mjs`、`bobo/plugins/experience-reflect.mjs`、
`bobo/command-proxy/lib/index.js` 这三个是**有**的。

另外预设还会引用 `../scripts/camoufox_debug_server.py`（本项目没有这个脚本）与
`@deepseek-ai/dsh-persona` 等内核包（内核里是有的）。

**这不是本次迁移的缺陷，是内容依赖**：市场预设是给 BoBo-Handyman 的完整插件集打包的。
要让它们真正可用，需要从参考项目继续迁移上述 5 个包 + camoufox 调试 MCP server。

**界面不会静默**：`repo.ts` 的 `unresolvedRows()` 会扫已装预设的 `agent.cordis.yml`，把指向
不存在文件的装配行收进条目的 `unresolved` 字段；`repo-tab.tsx` 在卡片和安装确认弹窗上显式
列出它们。`plugin.baisc.md` 的第 4 级退级策略要求「严禁静默半工作」，这条就是照着做的。

### 6.2 工具 tab 现在是空的

线上 `tools/index.json` 的 `plugins` 是 `[]`。而 8 个预设里有 5 个声明了
`requires: ["bobo-crawl-tool", "bobo-proxy-tool"]`：

- `bobo-proxy-tool` **本项目已有**（`bobo/command-proxy`，包名就是 `bobo-proxy-tool`）；
- `bobo-crawl-tool` 没有。

所以预设卡片上的 `requires` 提示会指出缺哪一个，但**没有可安装的工具能补上**，除非先往市场
的 `tools/` 命名空间里放工具包。

### 6.3 裸包名的解析是未决项

`repo-core.mjs::rewritePresetPaths` 原本会把 `@deepseek-ai/dsh-persona` 这类裸包名也改写成
`file:///` 绝对 URL，解析锚点是 `<appRoot>/dsh/node_modules/.pnpm/node_modules`（参考项目的
安装树）。本项目**刻意传空的 `resolveFrom`**，让裸包名原样保留：

原因是在本项目里那条锚点会解析到 `E:\SmartBoBo\dsh\node_modules\.pnpm\**` —— **桌面壳自己的
重复副本**，不是运行中内核的那一份。拿它改写会让预设行与内核分裂模块身份，比原样保留更糟。

**待验证**：Include 子树里的声明行能否按裸包名解析到内核的包。参考项目的结论是「loader 的
自带解析通道只覆盖 `<DSH_HOME>/profiles/**`」，若这里也如此，则需要在 §3 重启后看
`plugin_manager` 的 `list_plugins`，`preset-reverse` 这一行会带上激活失败的诊断。届时正确的
修法是把内核的 node_modules 路径作为锚点传进去（不能再从插件自身位置推）。

### 6.4 其它

- `minAppVersion`（市场里统一是 `"2.1.1"`，那是 BoBo-Handyman 的 App 版本号）**没有做门禁**，
  本项目也没有可比的版本基准。
- 本项目的经验池闸门在 `.dsh/profiles/web/cordis.patch.yml` 里写死了 `config.preset` 为
  `reverse` / `paper` / `report`；市场里只有 `reverse` 和 `report`，**没有 `paper`**（对应的
  是 `empirical` / `review`）。两套体系各自独立，装市场的预设不会自动激活经验池闸门。
- 卸载只认 `.bobo-market/state.json` 与技能目录里的 `.market-meta.json`；手工放进
  `.agent-presets/` 的预设不会被市场 UI 卸掉（这是参考项目的设计，用于保护用户自建内容）。
- 「工具」安装会往预设的 `agent.cordis.yml` 里插托管块
  （`# --- repo-managed: tool <id> v<version> ---`）。参考项目这一步**没有事务性保障**；
  本项目同样如此。装工具前建议备份一次 `.dsh/.agent-presets/`。

## 8. 与参考项目的三处偏差

都写在代码原位，将来从 `E:\BoBo-Handyman` 同步 `repo-core.mjs` 时按这三条重新打：

1. `rewritePresetPaths(text, appRoot, boboRoot?, resolveFrom?)` —— 多两个可选参数。参考项目把
   bobo 包写死在 `<appRoot>/dsh/packages/bobo`、解析锚点写死在 `<appRoot>/dsh/...`；本项目
   bobo 包在 `<appRoot>/bobo`，且不解析裸包名（见 §6.3）。缺省值保持参考项目语义，不影响上游行。
2. `installPreset({ ..., boboRoot, resolveFrom })` —— 透传上面两个参数。
3. selftest 里那三个「真仓库根下裸包名改成 file URL」的用例，换成本项目的策略断言
   （显式 `boboRoot` 生效、空 `resolveFrom` 下裸包名原样保留）。

另外 `eslint.config.mjs` 把 `src/host/service/repo/*.mjs` 与 `market-core.d.mts` 加进了
`ignores`，理由是逐字复制、格式由上游决定（与已有的 `packages/*/skills` 同类处理）。

## 10. 后端接口一览

全部挂在插件自己的前缀下（`server/index.ts` 里逐条字面量注册，按 `plugin.baisc.md` 的
「路由 path 不入常量模块」执行）：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/tauri/extension/repo/list?ns=presets\|tools\|skills` | 目录 ∩ 本地安装，合并成 UI 行（含 `status`） |
| GET | `/api/tauri/extension/repo/detail?ns=&id=` | 详情 markdown（带版本键缓存） |
| POST | `/api/tauri/extension/repo/install` | 下载 + sha256 校验 + 安装；`{ ns, id, scope? }` |
| POST | `/api/tauri/extension/repo/uninstall` | 卸载，回传被牵连的工具 id |
| POST | `/api/tauri/extension/repo/scope` | 工具 → 预设作用域（改写托管块） |
| POST | `/api/tauri/extension/repo/category` | 本地分类（只动 state） |
| GET | `/api/tauri/extension/market/search?q=&cursor=` | 第三方技能聚合搜索（含每源健康） |
| GET | `/api/tauri/extension/market/detail?id=` | 技能详情（SKILL.md / 文件清单 / 能力披露） |
| GET | `/api/tauri/extension/market/file?id=&path=` | 单文件预览 |
| POST | `/api/tauri/extension/market/install` | 逐文件安装到 `<DSH_HOME>/skills/` |

**没有独立的「更新」接口**：版本相同时装包核心返回 `already-installed`，版本不同时做安全替换
（且校验 `.market-meta.json` 归属，失败还原旧目录）。前端只是比对 `version` 与
`installedVersion` 把按钮文案换成「更新」，打的是同一个 install 接口。
