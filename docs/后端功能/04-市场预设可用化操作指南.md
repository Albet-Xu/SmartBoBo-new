## 2. 构建与部署

### 2.1 命令

```bash
cd E:\SmartBoBo\dsh
pnpm --filter dsh-tauri-extension build
```

产物：`dsh/packages/dsh-tauri-extension/dist/{index.js, client.cjs, index.d.ts, repo-core-*.js}`。

### 2.2 为什么不把 profile 的 link 指到工作区

03 的指南里写的是「改 profile 的 link 指向本地构建产物」。实测**这条走不通**，原因有三个，
都在本文这轮里逐个踩到：

1. `dsh/packages/dsh-tauri` **没有 `dist/`**（从未构建）。工作区插件里的 `import ... from 'dsh-tauri'`
   会解析到那个没构建的 workspace 包 → 直接 `ERR_MODULE_NOT_FOUND`。
2. 工作区源码（`44d1e5f7` 之后）用 `import { guard } from 'dsh-tauri'`，而**运行中的那份 `dsh-tauri`
   不导出 `guard`** → `SyntaxError: The requested module 'dsh-tauri' does not provide an export named 'guard'`。
3. 工作区源码用 `dsh-h3` / `dsh-h3/utils`，**运行环境里没有这个包**。

也就是说：工作区 `dsh/packages/dsh-tauri-extension` 是「新底座」世代，而 `vendor/dsh-resources/`
里跑的是**旧底座**世代的构建。把 link 指过去等于换底座，会连带 `dsh-tauri-ui`、`dsh-tauri` 等
一整套插件都要重建。

### 2.3 实际做法：把产物覆盖进现有位置

保持模块位置不变，只换代码 —— 这样裸导入的解析链（`vendor/dsh-resources/node_modules/**`）
完全不变，风险最小：

```bash
cp -r "E:/SmartBoBo/dsh/packages/dsh-tauri-extension/dist/." \
      "E:/SmartBoBo/vendor/dsh-resources/node_modules/dsh-tauri-extension/dist/"
```

旧产物已备份到 `E:\SmartBoBo\.temp\dsh-tauri-extension-dist-backup\`。

### 2.4 为这条路补的两个洞

- **`dsh-h3` 缺失**：已把内核工作区的 `dsh-h3@0.2.1` 复制到
  `vendor/dsh-resources/node_modules/dsh-h3`。它自身只依赖 `h3`（vendor 里已有 2.0.1-rc.31）。
- **`guard` 缺失**：`guard` 是宿主 `dsh-tauri` 的**请求安全中间件**（校验可信 Host/Origin、
  变更类请求限本机、跨域拒绝、把 `ctx.connection` 的拒绝结果透出），不能删。
  已把它原样移植成本包内的 `src/host/server/guard.ts`（只依赖 `dsh-h3/utils` 的
  `getServerContext`），`server/index.ts` 改为从本地导入。删掉它会直接丢掉 CSRF 与本机限制。

### 2.5 回滚

```bash
cp -r "E:/SmartBoBo/.temp/dsh-tauri-extension-dist-backup/." \
      "E:/SmartBoBo/vendor/dsh-resources/node_modules/dsh-tauri-extension/dist/"
```

`vendor/dsh-resources/node_modules/dsh-h3` 可以直接删（删掉就回到「工作区产物无法加载」的状态）。

### 3.2 根因二：裸包名解析锚点（本轮的关键修复）

DSH 0.2.0 的 `agent-preset-registry` **不扫任何目录、只认声明行**。声明挂在
`<DSH_HOME>/.agent-presets/<id>/decl.yml`，而 loader 的自带裸包名解析通道只覆盖
`<DSH_HOME>/profiles/**`。所以声明里的 `@deepseek-ai/dsh-agent-preset` 必须**在装包时改写成
`file:///` 绝对 URL**，否则就是本文开头那 8 条 `failed to import`。

`repo-core.mjs::rewritePresetPaths` 本来就有这个改写能力，决策点在**锚点选哪里**：

| 锚点 | 后果 |
| --- | --- |
| 插件自身位置（`vendor/.../dsh-tauri-extension/dist/`） | 解析到 `dsh/node_modules/.pnpm/**`，那是**桌面壳自己的重复副本**，与运行中的内核分裂模块身份 |
| 空锚点（不改写，保持裸名） | 本次实测的失败态：8 条全部 `failed to import` |
| **宿主 kernel 入口**（已采用） | 解析到内核那一份，身份一致 |

实现（`src/host/service/repo.ts`）：

```ts
const RESOLVE_FROM: string[] = kernelResolveAnchors()

function kernelResolveAnchors(): string[] {
  const entry = process.argv[1]          // node <kernelDeps>/@deepseek-ai/dsh/lib/bin.js
  if (entry === undefined || entry === '') return []
  try {
    createRequire(entry).resolve('@deepseek-ai/dsh-agent-preset')
    return [entry]
  } catch { return [] }                   // 锚点不可用 → 退化成不改写，而不是改坏路径
}
```

校验过的 20 个裸包名（预设会用到的全部）在该锚点下 **20/20 可解析**。装出来的效果：

```
decl.yml:  name: 'file:///C:/Users/.../dsh/node_modules/@deepseek-ai/dsh-agent-preset/lib/index.js'
           name: 'file:///E:/SmartBoBo/bobo/plugins/bobo-common.mjs'
```

8 个预设 267 条 `name:` 行，238 条被改写；剩下的 29 条是 `cordis:group` 内建与
`name: "逆向模式"` 这类**元数据行**（不是包名），按设计不动。

> 这一步改的仍是那三处「与参考项目的偏差」之外的新增内容，同步上游时按文末清单重打。

### 3.3 根因三：`BOBO_ROOT` 未设置

预设的 MCP 行写的是：

```yaml
config:
  command: ../.venv/Scripts/python.exe
  args: ['../scripts/reverse_memory_server.py']
  cwd: !!js process.env.BOBO_DSH_ROOT || process.cwd()
  env:
    BOBO_ROOT: !!js process.env.BOBO_ROOT || ''
```

- `cwd` 由 `BOBO_DSH_ROOT` 决定，`../scripts/` 要落在仓库根的 `scripts/` → **必须是 `<repo>/dsh`**。
- `BOBO_ROOT` 会被回传进 MCP 子进程，`scripts/*_memory_server.py` 靠它找
  `skills/*/memory_store.py`。**宿主进程里没设就是空串** → 报
  `ModuleNotFoundError: No module named 'memory_store'` 或
  `[paper-memory] 找不到 paper-experience/memory_store.py`。

`启动.cmd` / `启动.sh` 已同时导出这两个变量（原先只有 `DSH_HOME`）。

## 7. 出错时怎么查

1. **面板整个消失**：看启动日志有没有
   `does not provide an export named` / `ERR_MODULE_NOT_FOUND`。多半是 `dist` 覆盖后
   裸导入解析链被破坏（检查 `vendor/dsh-resources/node_modules/dsh-h3` 是否还在）。
2. **预设装上了但 roster 里没有**：没重启。`preset-includes.mjs` 只在启动时扫一次。
3. **roster 有 `preset-<id>` 但 `failed to import`**：裸包名没改写成 file URL。
   检查 `.dsh/.agent-presets/<id>/decl.yml` 第 9 行是不是 `file:///...dsh-agent-preset/...`；
   若是裸名，说明装包时 `kernelResolveAnchors()` 返回了空数组（`process.argv[1]` 不是内核入口）。
4. **某个 MCP 起不来**：`grep ModuleNotFoundError .temp/dsh-test*.log`。
   `memory_store` → `BOBO_ROOT` 没设；`html2text` / `lxml` → 见 §3.4；`camoufox` → 见 §5.1。
