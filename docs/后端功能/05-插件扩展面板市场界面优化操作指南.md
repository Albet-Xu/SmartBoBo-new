## 3. 界面结构：改前改后

### 技能 tab

```
改前： 标题行(打开目录/从技能市场安装/导入仓库/新建技能)
       技能 4/4   [搜索] [刷新]
       [全部|内置|自定义]              ← 只在来源 > 1 时才渲染
       技能卡片（2 列）
       └─ 市场靠模态框打开

改后： 标题行(打开技能目录/导入仓库/新建技能)
       技能 4/4   [搜索] [刷新]        ← 仅本地视图显示
       [全部|内置|自定义|技能市场]      ← 恒定渲染
       ├─ 本地视图：技能卡片（2 列）
       └─ 市场视图：内联搜索 + 每源健康 + 折叠卡片 + 加载更多
          └─ 详情 / 文件预览 / 安装确认仍是嵌套模态框
```

「技能市场」是唯一的视图开关：它激活时其余三个 pill 一起失活，避免出现
「内置 + 技能市场」同时高亮的怪状态。本地视图的搜索框与刷新按钮在市场视图隐藏 ——
市场面板自带搜索与刷新，避免两个搜索框互相打架。

### 模式预设 / 工具 tab

```
改前： 标题 → 说明 → 计数+[搜索][刷新]
       ── 已安装 8 ──                  ← 一段标题
       卡片（1 列、整行绝对路径、较高）
       ── 可安装 0 ──                  ← 又一段标题
       卡片（2 列）

改后： 标题 → 说明 → 计数+[搜索][刷新]
       [模式预设市场 8 | 已安装 8]      ← 同款 Pill
       卡片（2 列，两个视图共用同一骨架）
```

两个视图的差别只在**数据过滤**和**动作**：

| | 市场视图 | 已安装视图 |
| --- | --- | --- |
| 数据 | 整个目录（含已安装项） | 只列 `installedVersion !== null` |
| 标签 | `可更新` / `已安装` / 版本 / 内置 / 分类 | 同左 |
| 动作 | 详情 · (作用域) · **安装 / 更新** | 详情 · (作用域) · **更新** · 卸载 |

市场视图必须包含已安装项，否则需求 5 的「更新按钮」没有地方显示。

### 卡片骨架（两个 tab 完全一致）

```
名称(等宽字体)  [可更新|已安装] [版本] [内置] [分类]
描述（最多 2 行，超出省略）
已安装版本: x.y.z · 大小 · 标签…
已挂载到预设: …              ← 仅工具
[依赖缺失] [装配缺失]         ← 紧凑标签，替代原来整句红字
                              详情 · (作用域) · 安装/更新 · 卸载
```

**卡片瘦身的关键是把绝对路径和完整警示文案挪出卡片**：

- 安装路径 → 卡片的 `title` 悬浮提示 + 详情弹窗新增的「安装位置」行 + 安装确认弹窗（本来就有）。
- `requires` / `unresolved` 的完整清单 → 详情弹窗新增的警示块 + 安装确认弹窗（本来就有）。
  卡片上只留一个 `依赖缺失` / `装配缺失` 标签，这样 2 列栅格里的卡片高度不会参差不齐。

栅格与技能一致：`grid-cols-[repeat(2,minmax(0,1fr))]`，窄屏 `max-[680px]` 退成单列。

## 4. 后端：目录缓存降级为「仅失败兜底」

**问题**：`repo.ts` 的 `loadIndex` 原本有 60 秒内存缓存 —— 你在云端更新完，点「刷新」
也刷不出来，因为缓存没到期就直接返回旧文档。用户看到的是「刷新没反应」。

**改法**：去掉 TTL 判断，每次 `list` 都真去拉；拉失败才回落到上次成功的文档，并继续用
现成的 `restored: true` 提示「市场站点不可达，当前展示的是上次缓存下来的目录」。

```ts
// 改前：TTL 内直接返回缓存
if (hit !== undefined && now - hit.at < INDEX_TTL_MS) return { doc: hit.doc, restored: false }

// 改后：先拉，失败才回落
async function loadIndex(ns) {
  const hit = indexCache.get(ns)
  try { const doc = await fetchIndex(BASE_URL, TOKEN, ns); indexCache.set(...); return { doc, restored: false } }
  catch (error) { if (hit === undefined) throw error; return { doc: hit.doc, restored: true } }
}
```

代价是每次打开 tab / 点刷新都会打一次市场站。目录只在按需操作时读，量可以接受。
实测启动后首次请求 `restored: false`，即确实走了网络。

**「更新」不新增接口**：装包核心对同版本返回已安装、异版本做安全替换并回传 `replaced`，
前端按 `status` 换文案即可。

## 8. 遗留

1. **「更新」按钮的实景未验证**。当前市场 8 个预设的版本与你本地装的一致（都是 `1.0.1`），
   所以状态全是 `installed`，页面上不会出现「可更新」。等你在云端发新版本后，
   `status` 会变成 `update-available`，市场视图里就会出现「可更新」标签与「更新」按钮 ——
   这条路径已经由单测覆盖（`repo-tab.test.tsx` 第 1 个用例断言市场视图里出现 `update` 按钮），
   但没在真机上看到过。
2. **工具 tab 仍是空目录**（市场 `tools/index.json` 是 `[]`），所以「工具市场 / 已安装」
   两个 pill 现在都会显示 0。
3. 技能市场里已安装的条目仍然按 `installState === 'installed'` 一律显示「更新」按钮
   （`skill-market-view.tsx`），没有区分「已是最新」。这是市场核心返回的状态粒度决定的，
   要细分得让 `market-core` 也走 `compareVersions`。模式预设/工具那边已经是精确的
   `update-available`，不受影响。
4. 缓存去掉 TTL 后，每次打开 tab 都会打一次市场站。站点不可达时有 `restored` 提示兜底，
   但如果它长期不可达，每次打开 tab 会各等一个请求超时（`fetchIndex` 没有显式超时设置）。
   如果想要更快的失败，可以给 `fetchIndex` 加 `AbortSignal.timeout(...)`。
