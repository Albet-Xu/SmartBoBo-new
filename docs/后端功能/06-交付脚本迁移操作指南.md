# 交付脚本迁移操作指南（report 三件套 + paper_report + pdf-extract）

> 迁移轮次：R2（交付脚本搬运）
> 日期：2026-10-13
> 来源：BoBo-Handyman `scripts/`（原样搬运，脚本自包含、无 camoufox 依赖）

## 1. 背景

report（文献汇报）与论文写作四模式的**交付物生成层**由五个独立 Python 脚本承担。
本项目此前只迁了经验池/记忆 MCP（`report_memory_server.py` 等），交付脚本本体一直缺失：
预设（市场装入的 8 个预设）与 `dbx/skills` 的提示词都按 `<BoBo根>/scripts/*.py` 引用它们，
缺脚本时模型会照提示词调用然后报"文件不存在"。

本轮把五个脚本迁入 `scripts/` 并补齐 Python 依赖。

## 2. 五个脚本各自做什么

| 脚本 | 职责 | 关键依赖 |
|---|---|---|
| `report_pptx.py` | deck plan（`02-叙事/slide-plan.json`）→ **可编辑** `03-产物/deck.pptx` + `notes.md`；渲染确定性（zip 成员时间戳固定，同 plan 同哈希） | python-pptx |
| `report_qa.py` | 机械质检（文字预算/越界/字号/证据链）+ PowerPoint COM 逐页渲染 PNG + 写 `04-评审/render-manifest.json`（pptx 与每页图片 sha256 指纹）；有 high 违规 exit=2 | python-pptx、pywin32（本机已装）、Pillow |
| `report_deliver.py` | 生成 `05-交付/汇报说明.md`（讲清汇报逻辑与文件职责）；`--check` 核对交付闸门 | 标准库 |
| `paper_report.py` | 生成《论文写作说明》（四模式 empirical/experiment/modeling/review）；`--check` 核对 | 标准库 |
| `pdf_extract_server.py` | PDF 读取 MCP（serverName=`pdf-extract`）：文字+表格转 Markdown，分批 20 页/4 万字符，无 OCR | mcp（已有）、pdfplumber |

五个脚本**自包含**：除 `pdf_extract_server.py` import 同目录已有的 `result_digest` 外，
互不引用、无浏览器依赖，可直接搬运。

### 3.1 Python 依赖（`uv sync` 安装）

```toml
"python-pptx>=1.0",   # report_pptx / report_qa
"Pillow>=10.0",       # report_pptx 图片缩放（fastembed 传递已装，显式声明）
"pdfplumber>=0.11.4", # pdf_extract_server（带 pdfminer-six / pypdfium2 传递）
```

pywin32（report_qa 的 PowerPoint COM 渲染）**不进 pyproject**：它随本机 Office 环境走，
参考项目同样不声明；`report_qa.py` 对 pywin32 缺失做了降级（`--no-render` 或报错提示）。

### 3.2 pdf-extract MCP 宿主层挂载（`.dsh/profiles/web/cordis.patch.yml`）

预设已按 `pdfServerName: pdf-extract` 与 `mcp__pdf-extract__pdf_extract_*` 引用该 MCP，
但本项目从未挂载。本轮按项目惯例（绝对路径，与三个 memory MCP 行同风格）补上：

```yaml
    - id: mcp-pdf-extract
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: pdf-extract
        transport: stdio
        command: 'E:\SmartBoBo\.venv\Scripts\python.exe'
        args: ['E:\SmartBoBo\scripts\pdf_extract_server.py']
        env:
          DSH_HOME: 'E:\SmartBoBo\.dsh'
          BOBO_ROOT: 'E:\SmartBoBo'
        toolCallTimeoutMs: 120000
        reconnect:
          enabled: true
          initialDelayMs: 500
          maxDelayMs: 30000
          maxAttempts: 10
```

挂载后宿主层单实例，所有会话可用；预设层不再重复挂（防双份进程）。

## 5. 已知限制与遗留

1. **report_qa 的 PowerPoint COM 渲染未实测**（本机未确认装有 PowerPoint）：
   `--no-render` 路径已验；COM 渲染路径代码原样保留，首次在装有 PowerPoint 的机器上跑
   report 预设时自然验证。渲染失败时脚本降级为 `rendered=false` 并记录 `render_error`，
   不会崩。
2. deck plan 的完整 schema（12 个 role、字符预算表）在报告预设的 `report-slides` 技能里，
   本轮未随脚本迁移（属 report 预设的 skills，市场装预设时已带）。若预设内 skills 缺失，
   属 R3 插件补齐轮范围。
3. `paper_report.py` 的四模式产物模板依赖各模式工作区的项目文件布局；空目录只验证了
   "能跑通并生成说明"，真实论文项目的生成质量由论文模式会话自然验证。
