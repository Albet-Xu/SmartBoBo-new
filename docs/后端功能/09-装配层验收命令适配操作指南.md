## 1. 定位与保留取舍

参考项目的测试分三层，acceptance.py 管**装配层**——插件自检查不到的
"预设挂不挂得上、技能发不发得出、提示词点名的工具名对不对得上"。

| 检查面 | 参考项目版 | 本项目适配版 |
|---|---|---|
| 启动 | dsh 源码仓 `apps/cli/lib/bin.js --patch` | **打包内核** `bin.js --profile web`（DSH_KERNEL / APPDATA 默认路径） |
| 预设 | 自建 `dsh/packages/bobo/presets` + 随包预设，preset.yml 结构校验 | **市场安装** `.dsh/.agent-presets`，agent.cordis.yml / decl.yml 解析 + file:// 引用命中磁盘 |
| 技能 | 播种（seed-skills.js）后比对内置技能 | **用户级技能根** `.dsh/skills`（bobo-env / db-extraction），无需播种 |
| 代理池命名空间 | 同 settings/describe 断言 | 同（保留） |
| 装配一致性 4a-4c | 预设/插件/闸门工具名交叉核对 | **同款保留**（灵魂检查） |
| 装配一致性 4d-4f | base-rows 模板一致性 / command-proxy 不变式 / lib 引用 | 换为**采集引擎脚本存在性**（crawl-tool → run_cloak.py）；lib 引用并入结构校验 |
| 上游守卫 | check-upstream-untouched.sh | **删**（本项目无上游白名单机制） |
| Cloak 守卫 | 无 | **新增**：scripts/ 与 bobo/ 源码零 camoufox 引用 |
| 插件自检 | 同 | 同（现场扫 --selftest） |
| Python 测试 | pytest -q 全仓 | pytest -q，**testpaths 限定 dbx/tests**（dsh/source 上游 SDK 测试不属本项目） |
| DSH_HOME | bobo-data/dsh | **项目内 `.dsh`**（与启动脚本一致） |

新增 `--skip-live` 开关：跳过检查 1-3（起服务），只跑静态检查 4-7——改静态装配时
不必等 300s 启动。

## 2. 用法

```powershell
cd E:\SmartBoBo
.venv\Scripts\python.exe scripts\acceptance.py              # 全跑（默认端口 7085）
.venv\Scripts\python.exe scripts\acceptance.py --skip-live  # 只跑静态检查（约 20s）
.venv\Scripts\python.exe scripts\acceptance.py --keep       # 跑完不关服务（排障）
.venv\Scripts\python.exe scripts\acceptance.py --port 7086  # 换端口
```

退出码：0 全过 / 1 有断言失败 / 2 环境不具备（端口占、内核缺、依赖缺失）。

## 3. 七组检查

```
0. 环境前置    内核/patch/预设根/插件/技能源/.venv/node/PyYAML/端口
1. 启动        打包内核 dsh web --profile web（与启动脚本同 env），抓 ?token=，换 cookie
2. 预设挂载    结构校验（YAML 可解析 + file:// 引用命中磁盘）→ 8 预设逐个 session/create
3. 技能发现    每会话 skills/list 断言用户级技能全在；settings/describe 断言 proxy-pool
4. 装配一致性  预设/插件/闸门的 mcp__ 引用 ↔ serverName 声明交叉核对 + 采集引擎脚本存在
5. Cloak 守卫  scripts/ 与 bobo/ 源码（.py/.ts/.tsx/.mjs/.js，排除 lib/node_modules）
               零 camoufox 引用——唯一浏览器引擎是 CloakBrowser
6. 插件自检    现场扫 bobo/plugins/*.mjs 的 --selftest，逐个退出码
7. Python 测试  pytest -q（testpaths=dbx/tests）
```

预设/技能/插件清单**一律现场扫磁盘**，新增不必回来改常量。

## 6. 已知限制

1. **检查 1-3 需要空闲的 7085 端口与约 5 分钟**（内核启动 + 8 预设建会话）。
   常驻 7075 实例不受影响（不同端口，且只杀自己 spawn 的进程树）。
2. 验收会在 `.dsh/sessions` 留下会话记录（与手工验收同副作用）。
3. 上游守卫（check-upstream-untouched.sh）未迁：本项目 dsh 是打包内核 + vendor
   目录，无"上游源码白名单"机制；`dsh/` 工作区源码的保护靠 AGENTS.md 约定。
4. base-rows 模板一致性（参考版 4f）未迁：本项目预设来自市场安装，无本地模板；
   预设行的漂移由检查 2（结构校验）+ 检查 4（工具名归属）覆盖。
