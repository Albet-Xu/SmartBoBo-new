# 市场预设「依赖缺失去误报」修复操作指南

> 修复日期：2026-10-13
> 触发：用户反馈「模式预设」卡片一直显示"依赖缺失"，但迁移后功能实际都已就位

## 1. 根因

三层链路叠加造成的**误报**，与本地功能是否真的缺失无关：

1. **前端判定过粗**（`repo-tab.tsx`）：
   `missingDeps = entry.requires.length > 0`——只要后端返回的 `requires` 非空
   就打"依赖缺失"标签，**不检查依赖是否已满足**。
2. **`requires` 是线上目录的静态元数据**：市场服务器（47.102.138.180）的
   `presets/index.json` 里，5 个预设条目带 `requires: ["bobo-crawl-tool", "bobo-proxy-tool"]`
   （参考项目 `build_market.py` 发布时从 DETAILS.md 生成，不感知任何本机供给）。
3. **本机的真实供给不在市场的账上**：这两个工具本项目都有——
   `bobo/tool-acquisition` 的 npm name 就是 `bobo-crawl-tool`、
   `bobo/command-proxy` 的 npm name 就是 `bobo-proxy-tool`——但它们是预设用
   `file:///` **直挂的本地包**，不经市场安装、不在 `.bobo-market/state.json` 里。
   前端拿不到"已提供"的证据 → 误报。

功能层面从头到尾都是好的（R5 验收 41/41 已证），只是 UI 判定缺了"本地已提供"这一路。

## 2. 修复方案：后端过滤，前端不动

在 `dsh-tauri-extension` 的 `repo list` 接口组装预设条目时，把 `requires` 里
**已被满足**的项过滤掉——前端逻辑不用改，`requires` 空了标签自然消失。

### 已提供集合（provided）的两个来源

```
市场已装工具 id   ← listInstalled() 的 tools（经市场安装、在 state.json 里）
本地包名          ← 扫 bobo/*/package.json 的 name 字段（file:/// 直挂的那批）
```

### 改动

```
dsh/packages/dsh-tauri-extension/src/host/service/repo/repo-core.mjs
  + satisfyRequires(requires, provided)   纯函数：过滤已满足项，不改入参
  + selftest 5 例（全提供/部分/无集合/非法入参/不改入参）

dsh/packages/dsh-tauri-extension/src/host/service/repo.ts
  + localToolPackageNames()               扫 bobo/*/package.json 收集 npm name
  + list() 组装 presets 条目时 requires: satisfyRequires(row.requires, provided)
  + readdirSync import
```

构建与部署（本项目既有流程，见 04 号文档 §2）：

```powershell
cd E:\SmartBoBo\dsh
pnpm --filter dsh-tauri-extension build
# 产物复制到 vendor（profile 的 link 指向这里）
cp -r dsh/packages/dsh-tauri-extension/dist/. `
      vendor/dsh-resources/node_modules/dsh-tauri-extension/dist/
```

```
✔ requires：部分已提供 → 只剩缺的

✔ requires：不改动入参数组
repo-core selftest 通过：100 个用例
```

### 3.2 真实内核 API 端到端（临时端口 7098）

修复前（线上目录原样透传）：crawl 等 5 个预设 `requires: ["bobo-crawl-tool","bobo-proxy-tool"]`。

修复后：

```
GET /api/tauri/extension/repo/list?ns=presets
预设条目: 8  requires 非空: 0 个（全部清空）
单条示例：crawl → requires=[] status=installed
```

`bobo-crawl-tool`/`bobo-proxy-tool` 被本地包名扫描命中 → 判定已提供 → 过滤；
若未来某预设真引用了本机没有的工具（如 `bobo-xyz-tool`），仍会如实显示"依赖缺失"。

## 4. 影响面与限制

1. **前端零改动**：`repo-tab.tsx` / 安装对话框的展示逻辑保持原样。
2. **线上目录不动**：`index.json` 的 `requires` 照旧原样存储；过滤只发生在
   本机 `repo list` 出口。
3. **未真正安装的依赖仍会显示**：provided 集合只认"市场 state 里的工具"与
   "本地 bobo/ 包名"；两者都没有的依赖项照报不误（这是设计意图）。
4. `dsh/packages/dsh-tauri-extension` 是本项目唯一改动的内核工作区包；
   vendor 副本已同步，内核运行时加载的是 vendor 副本。
