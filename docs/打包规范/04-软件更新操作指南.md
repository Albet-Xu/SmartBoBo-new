# SmartBoBo 软件更新操作指南（v0.5.0）

> 版本：**v0.5.0**（2026-10-14）
> 关联：`03-瘦安装包与云端依赖分发操作指南.md`
> 能力：版本感知 + 托盘一键更新 + 已装 profile 迁移器

## 一、更新模型总览

对齐 dsh-desktop 的 desktop-updater 思路，但按我们 42MB 瘦包架构简化为**整包覆盖**：

```
用户侧：
  启动后空闲 → 静默检查云端 manifest.app.version
  → 托盘菜单显示「更新到 vX.Y.Z」
  → 点击 → 下载 setup.exe(%TEMP%) → sha256 校验
  → 拉起静默安装 cmd（等本进程退出 → setup /S → 重启应用）
  → 应用自动退出 → 安装覆盖 → 新版自动拉起

发布侧：
  打新版 → finalize_manifest.py 写入 app 段
  → 上传 setup.exe + manifest.json → 完成
```

**关键性质**：
- **不卸载**：NSIS 覆盖安装，`InstallDirRegKey` 记住路径，`BoBoData` 与已下载的托管依赖原样保留；
- **不自动静默**：只提示，用户点确认才更新；
- **原子性**：新包先落 `%TEMP%` 并 sha256 校验，通过才执行安装；
- **回退友好**：安装失败时 BoBoData 永远安全，用户可重装旧版。

## 二、用户操作（发给用户的说明）

1. 托盘找到菠萝图标（可能折叠在 `^` 里）；
2. 菜单显示「**更新到 v0.5.0**」即有新版；点击后应用会自动下载、安装并重启；
3. 若显示「检查更新」，点击可手动刷新检测；
4. 若网络不通，更新失败会在日志留痕（`BoBoData/logs/launcher.log`），不影响当前使用。

**不想用托盘更新？** 直接去官网下新 `setup.exe` 双击安装即可——**不需要先卸载**，覆盖装完就是新版。

## 三、发布者操作（你发新版时）

```bat
:: 1. 改版本号（两处保持一致）
::    packaging\nsis\smartbobo.nsi        → PRODUCT_VERSION "0.5.1"
::    packaging\build_installer.cmd       → set "VERSION=0.5.1"
::    packaging\launcher\launcher.py      → APP_VERSION = "0.5.1"

:: 2. 一键构建（自动写 manifest.app 段 + sha256）
packaging\build_installer.cmd

:: 3. 上传两个文件到服务器
::    packaging\dist\SmartBoBo_0.5.1_x64-setup.exe
::      → /BoBo/BoBo-setup/releases/
::    packaging\dist\deps\manifest.json
::      → /BoBo/BoBo-setup/deps/
```

云端 `manifest.json` 的 `app` 段长这样（`finalize_manifest.py` 自动生成）：

```json
"app": {
  "version": "0.5.1",
  "setup": "SmartBoBo_0.5.1_x64-setup.exe",
  "setupSha256": "…",
  "size": 42350652,
  "notes": "本次更新说明（可选，展示用）"
}
```

## 四、已装旧版怎么办：profile 迁移器

**问题**：`.dsh-template` 只在首启实例化一次；旧安装的 `BoBoData/.dsh` 收不到模板修复（如 browse 目录选择器、裁剪插件）。

**方案**：启动器启动时运行 `migrate_profile()`，按 `PROFILE_SCHEMA_VERSION`（当前 = 2）增量补齐，写 `BoBoData/.dsh/profile-schema-version`。

| schema | 内容 | 触发条件 |
|---|---|---|
| v2 | 追加 browse 目录选择器（禁用 auto + insert browse 对） | `cordis.patch.yml` 里没有 `dsh-host-directory-picker-browse` |

**迁移原则**：
- **追加式**，不重写整个文件（用户手改过的内容保留）；
- **幂等**：目标状态已存在则跳过；
- **失败不阻断**：迁移异常只打 WARN，照常启动；版本号不推进，下次启动重试。

以后模板有新修复时：
1. `PROFILE_SCHEMA_VERSION` 递增（如 3）；
2. 在 `migrate_profile()` 加对应幂等迁移块；
3. 重新打包发布。

## 五、涉及文件

| 文件 | 变更 |
|---|---|
| `packaging/launcher/launcher.py` | `APP_VERSION`、`check_for_update()`、`run_self_update()`、`migrate_profile()`、托盘「更新」菜单项、启动后 8s 空闲检查 |
| `packaging/finalize_manifest.py` | **新增**：构建收尾写 `manifest.app`（版本+sha256） |
| `packaging/build_installer.cmd` | 5 步流程，第 4 步调 finalize_manifest |
| 云端 `deps/manifest.json` | 新增 `app` 段 |

## 六、边界与限制

| 场景 | 行为 |
|---|---|
| 更新下载失败 / sha256 不匹配 | 打日志、删除临时文件，应用继续用旧版 |
| 安装覆盖时应用未退干净 | 助手 cmd 先 `ping` 等 3s 再跑 setup；若仍被文件锁挡住，setup 失败但 BoBoData 安全，用户可手动重装 |
| 托管依赖大版本升级（如内核 0.2→0.3） | **不在本机制内**——setup 覆盖的是启动器+应用代码；内核升级需改 `manifest.deps` 的 sha256 并让 `_dep_present` 按版本判断（v0.6 计划） |
| 无网环境 | 更新检查静默失败；用户可用 U 盘拷 setup.exe 覆盖装 |
| 同时装了多份 SmartBoBo | 每份独立检查/更新自己的目录（manifest 是全局的，路径各自解析） |
